# Contributing

Thanks for your interest in improving Bouncing! Contributions are welcome.

## Before you start

- Check the existing issues and pull requests before opening a new one.
- For a significant change, open an issue first to discuss the proposal.
- Keep contributions focused; unrelated changes belong in separate pull requests.

## Reporting a bug

- Search existing issues to avoid creating a duplicate.
- Include clear steps to reproduce the problem.
- Describe what you expected and what actually happened.
- Mention your browser, operating system, and screen size when relevant.
- Add screenshots or a short recording if they help explain the issue.

## Proposing a change

- Fork the repository and create a descriptive branch for your work.
- Make changes in small, focused commits with clear commit messages.
- Follow the existing HTML, CSS, and JavaScript style.
- Avoid adding dependencies unless the change truly needs them.
- Update documentation when behavior, controls, or setup instructions change.
- Test the game in a browser, including keyboard and pointer controls.
- Check that the layout remains usable on a narrow screen.

## Submitting a pull request

- Push your branch to your fork and open a pull request against the main branch.
- Explain the problem and solution in the pull request description.
- Link related issues using GitHub's closing keywords when appropriate.
- Include any relevant test steps and screenshots.
- Keep the pull request limited to the agreed scope.
- Respond respectfully to review feedback and update your branch as needed.
- A maintainer may request changes before merging.

## Community

- Be respectful, constructive, and welcoming in discussions.
- Focus feedback on the work, not the person.
- Assume good intent and help keep the project friendly for everyone.
